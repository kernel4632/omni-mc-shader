# 绘制流程

当前只有最终绘制入口生效，其他效果和流程文件是已注明的占位。

```text
加载器绘制基础场景
    ↓ colortex0（场景颜色）、depthtex0（场景深度）
final.vsh / final.fsh
    ↓ 显式引入
rendering/final.glsl
    ↓ 调用
effects/debug.glsl
    ↓
屏幕画面
```

## 入口与效果的边界

`.vsh/.fsh` 使用加载器要求的固定名称，只声明版本和阶段并引入绘制文件。
`rendering/` 明确写出绘制顺序、读取什么、输出什么。
`effects/` 保存效果算法、选项及只服务这一效果的计算。
`common/` 只保存实际被多项效果使用的纯计算。

`rendering/terrain.glsl`、`transparent.glsl` 和 `lighting.glsl` 尚未接入。
不创建空的地形、阴影或合成入口，因为加载器会尝试执行它们。
第一版需要哪个绘制步骤，就新增对应的完整入口并明确接入。

## 中间画面

编号、格式、清除方式与用途在 `shaders/rendering/buffers.glsl` 维护。
当前使用加载器提供的 `colortex0` 和 `depthtex0`，没有自定义缓冲分配。
未来新增纹理前先确定生产者和消费者，再填写此文件并修改对应绘制流程。
说明文档帮助理解；代码与编号约定以主体文件为准。

## 如何新增一个效果

1. 在 `effects/` 建立以实际效果命名的 `.glsl`，写职责、调用位置和示例。
2. 算法和选项留在同一文件。只服务它的计算也留在这里。
3. 在实际需要它的 `rendering/` 流程中显式引入并调用。
4. 如果需要额外绘制步骤，创建对应入口，补充输入输出约定。
5. 在 `pipeline.properties` 声明实际需要的程序开关等加载设置。
6. 生成、检查，并在固定场景中验证。

菜单自动收集不会自动接入算法，也不会推断绘制顺序。
一项效果确实难读时，才拆进同名目录；按算法或实际内容拆分。
