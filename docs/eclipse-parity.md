# Eclipse 与 Omni 效果对照

本文件把 Eclipse（`references/Eclipse/shaders`，基于 Bliss 的改版）当作参考，逐类对照 Omni 现在能做什么、差在哪里、该不该合并。
它是只读调查的产物，不改任何代码；iterationT 的移植合同仍在 `docs/parity.md`，两者互不覆盖。
2026-10-17 按 `git log` 与当前 `main` 代码重写一次：把 `dev.127`–`dev.132` 新合并的一批 Eclipse 能力（后处理滤镜、体积雾体系、交互与细节、程序化草、环境与天气）从「未合并」移出并写清落点。

## 怎么读这份文档

- **第一列「效果」**：一类画面能力，例如月亮、体积云、水波。
- **第二列「Eclipse 的做法」**：Eclipse 侧的文件路径（相对 `references/Eclipse/shaders`）、关键函数名、它暴露给玩家的选项名和默认值。每个判断都带 `文件:行号`，行号来自文件真实内容。
- **第三列「Omni 现状」**：Omni 侧文件（相对 `shaders`）、函数、`OMNI_*` 选项与默认值。Omni 没有这项就写「无」。
- **第四列「差异与合并建议」**：先说状态，再给证据与差额。状态只有四种：
  - **已合并**：Eclipse 的算法（或同一套数学）已搬进 Omni，写清落点。
  - **近似**：能力在，但换了写法或只搬了一部分，写清差在哪。
  - **未合并**：Eclipse 这项在 Omni 没有对应，写清原因，并在括号里标是哪一类——`换来源`/`换模型`（Omni 用 iterationT 版本，能力在但不是 Eclipse 的）、`两套都留`（两边各有一套，都保留）、`技术上不可行`、`需要跨程序结构改动`、`按项目规则不写模组专用适配`。
  - **保持 Omni 现状**（并进「未合并」计数）：两边都有等价能力，但 Eclipse 的具体参数或做法没有搬，Omni 保留 iterationT 版本。

**怎么用它决定合并顺序**：先只读第四列。标着「已合并」或「近似」的已完成；「未合并」的按原因分类，`换来源`/`换模型`/`两套都留` 一般不必再动，`技术上不可行`/`需要跨程序结构改动` 才需要评估新方案。

**看之前先知道两件事**：

- Omni 现在的效果是一比一移植 iterationT 3.2.0（`docs/parity.md`），Eclipse 是另一套实现。所以很多「差异」不是缺功能，而是换了算法来源。这一列会写清属于哪种。
- 结构不同：Eclipse 在 `dimensions/` 放共享实现，`world0/`、`world-1/`、`world1/`、`world0_with_aether_flag/`、`world0_with_twilight_forest_flag/` 是薄包装（此结构判断未逐行确认）；Omni 用 `rendering/` 放绘制主体，`world*/` 是薄入口。

## 合并顺序与当前状态

本轮（`dev.127`–`dev.132`）从「未合并」移出并已落地的能力：后处理滤镜（色彩分级、镜头形变、胶片颗粒）、体积雾体系（洞穴雾、边界雾、下界三段体积雾、末地涡旋雾、时段雾）、交互与细节（玩家交互水面近似、受伤与低血量、原版区块淡入、水洼尺寸、材质 AO 与法线倍率、太阳色与辐照）、程序化草与体素编号通路、环境与天气（每群系环境、行星曲率、雪暴与沙暴、每日天气）、远景过绘防护与噪声远距衰减。这些都默认关闭或取中性值，默认画面不变。

按第四列状态统计（本表 34 行，含「保持现状」并入「未合并」）：

- **已合并 17 项**：月亮与月食、太阳色与辐照、程序化草、下界体积雾、末地涡旋雾、时段雾、每群系环境、雪暴与沙暴、每日天气、受伤与低血量、远景（DH）、后处理滤镜、色调与曝光（白平衡）、景深/散景（变形与色散）、材质 AO 与法线倍率、洞穴雾与边界雾、行星曲率。其中多项含**近似**子项，逐条见上表。
- **近似 5 项**：卷云/积雨云、积雪覆盖、雨点涟漪与水洼、星空、末地主岛光照。
- **未合并 12 项**，按原因分：`换来源`/`换模型` 9 项（体积云、水波模拟网格、水雾与焦散、天空与大气、GTAO、阴影、TAA 与抖动、泛光、闪电）、`两套都留` 1 项（LPV/间接光）、`按项目规则不写模组专用适配` 1 项（Photonics/Colorwheel/Caelum/Voxy 与体素反射）。

仍缺的项与原因是否充分（逐项给结论）：

- **波浪模拟（Eclipse 网格模拟）**：原因充分。Omni 用 iterationT 波浪贴图法线，玩家涟漪为近似；网格模拟依赖跨帧水面数据，属换算法来源，非缺陷。
- **LPV 细分**：原因充分。两边各有一套 LPV，Omni 保留自有实现（`docs/parity.md:375`）。
- **天空系数**（`Sky_Brightness`、`sky_coefficientRayleigh/Mie`）：原因充分。换用预计算大气，参数不可直接互换（合同 `docs/parity.md:17`）。
- **体素反射与模组（Photonics/Voxy/Colorwheel/Caelum）**：原因充分。符合「不为特定模组编写专用适配」的项目规则。
- **资源包天空**（`RESOURCEPACK_SKY`）：原因充分但性质不同。属`需要跨程序结构改动`/`技术上不可行`：Iris 无天空专用采样器，Eclipse 复用 `colortex9`，而 Omni 的九号画面已是草方块编号缓冲，直接冲突。
- **云逐层 `tallness`/`detail`/`distance` 与云渲染控制**：原因充分（换来源），但视觉可调面确实比 Eclipse 少。
- **`CROSSTALK`、曝光乘数/加亮变暗、自发光矿石/纹饰独立开关、景深焦距/光圈/手动对焦、闪电体积照亮**：均归入上表的对应行，原因 `换来源`，属能力在但参数面不同，不必强行合并。
