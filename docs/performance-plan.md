# 性能与重载优化执行计划

这份文件把“重载慢、帧率不稳、显存偏高、选项难懂”拆成可执行的小步，每步都有可复核的证据和验收条件。
调用位置：开发与审查时先读本文件，再动代码；进度变化时更新对应条目。
可复制示例：`python build.py verify`、`python build.py compile`、`python build.py check`。
关键取舍：先修结构带来的浪费，再谈算法替换；每个小步都能单独回退，不把半成品留在 `main`。

## 一、现状证据（2026-10-18 实测）

| 项目 | 现状 | 对照 |
| --- | --- | --- |
| 合成本体展开体积 | 约 12MB（拆分后） | iterationT `composite5` 约 123KB |
| 延迟三号展开体积 | 约 2.8MB | iterationT `deferred3` 约 81KB |
| 单个程序 include 次数 | 1453 次 / 72 个不同文件 | iterationT 单程序顶层 16 个文件，基本各一次 |
| 重载日志 | 21:42:11 建管线 → 21:42:20 就绪（约 9 秒），21:42:26 Physics Mod 注入失败 | 目标：3 秒内就绪 |
| 运行时 | 未做逐效果计时 | 目标：默认配置 1080p 稳定 90 帧以上（RTX 5060 笔记本） |
| 显存 | 未量化每张画面 | 目标：默认配置低于 6GB |

## 二、根本原因

1. **include 是复制粘贴，不是引用同一个文件。** 效果文件互相 include，每个效果又各自 include 公共头，形成网状依赖；同一个文件在一个程序里被插入几十次。`#ifndef` 只防重复定义，不防重复插入。
2. **一个程序包含了整个合成阶段的并集。** 拆分后仍未按“这个程序真正用到的效果”收敛，部分文件仍有重复的 include 行。
3. **没有按时间复用历史帧。** 屏幕反射、环境光、体积雾仍以固定采样数为主，没有统一接入半分辨率与时间重建。
4. **显存按最坏情况分配。** 缓冲只按维度区分，没有按功能开关缩尺寸或换格式。

## 三、执行顺序

### P0 编译与重载（先做，收益最大）

1. **把 include 改成树状。**
   - 每个 `rendering/*_pass*.glsl` 在第一个函数之前放一份有序依赖清单；效果文件不再 include 其他效果或公共头。
   - 顺序规则：公共头 → 输入声明 → 基础几何/材质 → 光照 → 天气与天空 → 水与雾 → 反射 → 后期。
   - 已知坑：输出声明要在效果函数之前、`COLORTEX8_2D` 要在公共头之前、`texCoord`/`texelCoord` 只能声明一次。
   - 验收：`build.expand` 得到 composite5 约 0.8MB；全部程序 `python build.py compile` 0 错误。
2. **清理重复 include 行。** 同一文件内相同路径只保留第一次；若去重后出现符号缺失，说明它原本靠重复插入传递可见性，必须同时调整清单顺序，而不是把重复行加回来。
   - 验收：展开次数 = 不同文件数（误差 0）。
3. **减少程序变体。** 统计每维度实际编译的程序；把只在特定功能开启时才有意义的计算程序继续用 `program.*.enabled` 关掉。
   - 验收：重载日志从“就绪”到“第一帧”少于 3 秒。

### P1 运行时（帧率）

4. **半分辨率屏幕反射。** 反射在 1/2 分辨率缓冲里追踪，按深度与法线做边缘感知放大，缺失处回退天空盒。
5. **体积雾与空气光半分辨率。** 步进在半分辨率上做，时间重投影复用上一帧；采样数随分辨率下降。
6. **随机采样 + 蓝噪声。** 把固定循环改成每像素随机偏移，靠时间累积降噪；替换部分固定多步采样。
7. **测量。** 固定场景（平原、森林、水下、雨天、末地），记录平均帧、1% 低帧和每效果开关的差值；没有数据的优化不算完成。

### P2 显存

8. **逐张画面登记**：分辨率、格式、写入者、读取者、是否可复用。
9. **按需缩尺寸**：屏幕反射、环境光、体积雾的半分辨率缓冲；阴影图近远分级。
10. **复用与降格式**：非 HDR 画面保持 8 位；能复用同一张画面的阶段合并；关闭功能时不分配图片（缓冲仍由加载器固定分配，不承诺运行时可别名）。
11. **验收**：默认配置下用外部工具记录显存峰值，写入 `docs/performance.md`。

### P3 选项与默认配置

12. **按页面重写标签**：页面名承担类别，选项名只写差异；术语换成日常说法；不用抽象比喻。
13. **默认配置重调**：以“第一眼有效果、1080p 可玩”为目标，重新定体积云、阴影、反射、雾的档位；动态模糊保持默认关闭。
14. **验收**：新玩家不看说明能说出五个主要选项的作用；默认配置截图与帧数记录在案。

## 四、每一步的验证与回滚

- 每步先跑 `python build.py audit`、`python build.py verify`、`python build.py compile`；P0 还要记录 `build.expand` 体积。
- 画面相关改动必须进游戏看同一场景，记录截图与帧数；离线通过不算完成。
- 任何一步让默认画面变化，先在提交说明里写清变化与原因，并保留上一提交可回退。
- 不在同一步混合结构重构与画面调参。

## 五、不做或暂不做

- VRS、帧图别名、DLSS 类神经超分：Iris 没有对应接口，写出来也无法生效。
- 模组专用适配（Photonics/Voxy/Caelum/Colorwheel）：按项目规则不写。
- 为压缩体积删除仍在使用的效果：体积目标不能以删功能为代价，除非用户明确要求。
